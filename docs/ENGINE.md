# Engine guide (for scene and spread authors)

The video is a web app (`app/`, TypeScript + three.js, run with bun + Vite) that renders any song time `t` deterministically — up to GPU canvas raster noise, see "Magazine" — at 1920×1080 (or at 2× that, 3840×2160, with `?scale=2`; see "Output scale" below). The same code drives the live preview and the offline 60 fps export. All of it is one scene, the magazine, which hosts the issue's spreads in the flatplan's running order.

## Running things

- Dev server (probably already running): `cd app && bun x vite` (no `bunx` on this machine). It defaults to port 5391 (`vite.config.ts`; 5173/5174 belong to another project here) and moves to the next free port if 5391 is busy — use the URL it prints. Preview: http://localhost:5391/?t=23.0 (space = play/pause, ←/→ = ±1 s, shift = ±5 s, `,`/`.` = ±1 frame, `h` = hide the UI; PageDown/PageUp = next/previous spread, landing just after its turn, the HUD showing its section and the spread up as `§verse1 ▸getthelook`; `l` = loop the spread on screen, from its turn in to the next turn (`l` again to stop; the HUD shows `LOOP`)). Add `&card=testcard` for a diagnostic scene (see "Diagnostic scenes").
- Stills (the main way to check your work — then LOOK at the PNGs with the Read tool): `cd app && bun scripts/render.ts stills --t 12.5,13.0,14.2 --out ../out/wip/stills`
- Legibility floor on stills (4.5:1, TREATMENT §6): from the repo root, `uv run app/scripts/legibility.py out/wip/stills/f_0016.00.png [...]` (or plain `python`, with numpy and pillow) prints each still's ratios and exits non-zero below the floor; its docstring says what it measures.
- Contact sheet of a time range: `bun scripts/render.ts sheet --from 1.5 --to 9 --n 16 --cols 4 --out ../out/wip/sheet.png` (`--times a,b,c` for chosen times; around page turns see "Page turns and the camera")
- Short video clip (to judge motion: extract frames with ffmpeg, or just trust the math): `bun scripts/render.ts video --from 20 --to 25 --out ../out/wip/clip.mp4 --preset veryfast`
- Keys check (TREATMENT §6, "Keys are load-bearing"; `src/keycheck.ts`): `bun scripts/render.ts keys --spreads 1` paints each face of those spreads (0 is the cover; all by default) at every 1/15 s, and around each key change, and fails, naming the spread, side, layer, times and where on the page, wherever a face changes under an unchanged key, a key comes back with another face, or either isn't a pure function of t; it warns where a new key paints the same pixels. About 30 ms a sample, nearly all of it reading back and comparing 15 MB faces: spreads 0–3 take under 2 minutes, all of them about 6.
- `--card NAME` (any mode) renders a diagnostic scene instead of the magazine, e.g. `--card testcard`. `--only a,b` loads only those timeline entries (an id that matches none fails at boot); the timeline is a single entry now (`magazine`, or the card), and an entry on screen that isn't loaded renders dark red, as a scene that failed does.
- Tests: `cd app && bun test` (pure logic in `tests/`: drawing paths, the grid and karaoke keys, the turn schedule, the curl, the bow and the settle, page ↔ world, the lamp, the stocks, the focus budget, the handheld camera; the guards on the spreads, `tests/sung.test.ts`: every focus box in frame and sharp while it's sung (type as soft as its `size` allows, a drawing to FADE), through the rendered camera, and every turn from the whole right page; and the keys check's verdicts on synthetic faces, `tests/keycheck.test.ts`). Typecheck both configs with `bun run typecheck`, or just your files: `bun x tsc --noEmit -p tsconfig.json 2>&1 | grep spreads/yourspread`.
- The render script prints `SCENE ERRORS` and browser console errors — read them.
- 4K: add `--scale 2` to any mode (`stills` then saves full-resolution 3840×2160 PNGs). Check your scene at both scales: downscaled, the 4K frame should look like the 1080p one, only sharper.
- Renders while files are being edited: run a server without live reload (`LV_NO_HMR=1 bun x vite --port 5190`) and pass `--url http://localhost:5190`; a live-reloading server reloads the page mid-render. Without `--url`, `render.ts` always starts its own private server, which runs without it.

## Data

- `lyrics` (`src/engine/lyrics.ts`): `lines[]` with `text,section,start,end,words[]`, each word `{w,start,end,conf}` (+ `syl` for hyphenated words) (word-level, aligned to the vocal). Find lines by content, never hard-code times: `const l = this.ctx.lyrics.get('it could be so fun')` → `l.words[3].start`. Helpers: `Lyrics.wordProgress(word, t)` (0..1 sung progress, piecewise across `syl` when a hyphenated word has per-part timings), `Lyrics.lineCharProgress(line, t)` (chars sung so far — for per-glyph wipes), `lyrics.findWords('look')`.
- `audio` (`src/engine/audio.ts`): `beats[]`, `downbeats[]`, `sections[]`, `beatAt(t)` (continuous beat index), `barAt(t)`, `timeOfBeat(i)`, `nearestBeat(t)`, `events('kick'|'snare'|'hat'|'vocal', t0, t1)`, `env(name, t)` for `rms|low|mid|high|vocal|drums|bass|other` (0..1), `hit(kind, t, halfLife)` decaying pulses.
- Every `Frame` already carries `f.a` = `{rms,low,mid,high,vocal,drums,bass,other,kick,snare,hat,vonset}` and `f.beat,f.bar,f.beatPhase,f.barPhase`.
- The loaders read only `data/lyrics.json` (from `analysis/align.py`) and `data/audio.json` (from `analysis/analyze.py`); if either is missing, boot fails with an error naming the file and the command that writes it.

## Magazine

The video is one scene, `magazine` (`src/scenes/magazine.ts`, helpers in `src/scenes/magazine/`): the default and only timeline entry, 0 → the end of the song. It owns the charcoal sheets (`sheets.ts`), the book, the camera and every page turn, all lit by one lamp (`src/engine/lamp.ts`, see "The world"), and hosts the **spreads** — content modules in `src/spreads/` that print the pages. This section is the mechanics; what goes on the pages (style bible, typography, flatplan, choreography, rules for spread authors) is `docs/TREATMENT.md`.

- **The flatplan** (`src/spreads/flatplan.ts`, batch-2 spec §2): the issue's running order, an entry per spread — its `id`, its `section` (whose lyric lines it prints) and when it comes up, `at`, a rule on the data: a section's start, the first downbeat at or after a sung word, the downbeat a bar before a section, or some beats after the entry before. Spreads are not one per section: verse 2 has two (the second on the downbeat at "But you're"), the bridge's comes up a bar early, on the drop, the ransom note's rips its page out instead of turning it (`how: 'rip'`), and the outro has two, the magazine closing onto its back cover between them. `resolveFlatplan(audio, lyrics)` times the entries and lays them on the leaves (`Resolved`: `start`, `how`, the leaves shown, the piles); it throws, naming the entry, on an unknown section, line or word, starts that don't strictly increase, turns closer than `CAM_BLEND_S`, or a turn with no page left to turn. `timeFlatplan` is the timing alone, without the checks (the preview's review aids).
- **Hosting**: `Magazine.init` builds one spread per flatplan entry, in order (`makeSpreads`, `spreads/registry.ts`: `SPREADS` keyed by entry id) — the cover (`spreads/cover.ts`), each spread built so far, and a placeholder (`spreads/placeholder.ts`: the section's title and its lyrics in karaoke; a section shared by two spreads is split between them where each comes up) for the rest. A real spread replaces its entry's placeholder there. Spreads are plain objects from factory functions, given a `SpreadCtx` (below); every function they expose takes song time `t`.
- **Leaves**: the book has 13 leaves (`LEAVES`, `page.ts`), each with a front and a back: leaf *k*'s front is page 2*k*+1, its back page 2*k*+2. Closed, the cover (leaf 0's front) lies on top of them all on the right. A turn moves the right page's leaf over to the left pile, so the spread it brings up shows that leaf's back as its left page and the next leaf's front as its right page. A rip (spread 10) tears the right page's leaf out instead: the left page stays, the next leaf's front comes up on the right, and the book is a leaf thinner, its pages skipping the torn-out two (pp. 18 and 21). The last turn (spread 13) closes the magazine onto its back cover — the last leaf's back, face up on the left pile — with nothing on the right. A spread shows `Resolved.left`'s back and `right`'s front (`null`: no page there — the cover has no left page, the back cover no right one), and draws only the faces it has.

### The `Spread` contract (`src/spreads/spread.ts`)

```ts
interface Spread {
  id: string;
  section: string;                  // its data/audio.json section
  pages: [number, number];          // left/right page numbers, for folios: ctx.pages (the cover: 0 and 1)
  drawPrint(side: Side, c: CanvasRenderingContext2D, t: number): void; // the print, in page units
  drawMarks(side: Side, c: CanvasRenderingContext2D, t: number): void; // the lipstick layer, in page units
  key(side: Side, layer: 'print' | 'marks', t: number): string;        // see "Faces and keyed redraw"
  camera(t: number): CameraPose;
  lift?(t: number): number;         // the whole magazine's height above the sheets (world units)
  panels?(t: number): Panels;       // a gatefold's fold-out (Spread<FaceSide>): see "The fold-out"
}
```

- A spread is built (`SpreadFactory`) from its `SpreadCtx` (`flatplan.ts` `spreadCtx`): `audio`, `lyrics`, its entry's `id` and `section` (find its lines with `cues.ts`'s `sectionLine`, within its section), `start`, `turnAt` (when the turn out of it starts: undefined for the last spread, which nothing turns away from — `turnOut(ctx)` gives it, and throws there), `leaves: { left, right }` and `pages`, its folios' numbers from its leaves (0 where it has no page). Print folios from `ctx.pages`, never from the spread's position in the book: after the rip, the pages skip the two torn out.
- `Side` is `'L' | 'R'`. The draw functions get a cleared, transparent face canvas scaled to page units, in the default context state (the scene saves and restores around each call, even when the draw throws — so keep your own `save()`/`restore()` balanced), and draw the whole layer. It is a plain canvas, not a `Layer2D`: `setTransform`/`resetTransform` drop the page-unit scale, and `filter`, `shadowBlur` and `shadowOffset*` lengths are canvas px — scale them by `c.getTransform().a` (canvas px per pu), as the cover's masthead blur does.
- `CameraPose` is `{ x, y, dist, tilt, roll }`: the target in spread space (world units, below), the distance to it, `tilt` (0 = looking straight down; positive = the camera moves toward −y and looks up the page) and `roll` (positive turns the image clockwise), in radians. `FRAME_SPREAD` (`{ x: 0, y: 0.49, dist: 1.98, tilt: 0.1, roll: 0 }`) is the open spread with a band of sheets either side; `lerpPose(a, b, u)` interpolates poses, the distance in log space (an even zoom).
- `camera(t)` is also evaluated for up to `CAM_BLEND_S` past the *next* spread's start: the camera's move to the next spread blends from this spread's pose, read at the current t. Keep it defined (and sensible) there.
- `lift(t)` is read from the open spread (during a turn, the one being turned away from). Only the cover has one so far: its drop onto the sheets, over long before its flip.

### Page units and world units

- **Page units (pu)**: a page is `PAGE` = 770 × 1000 pu (`src/engine/pagesize.ts`, re-exported by `layout.ts`), origin top-left, y down, at every output scale. At `FRAME_SPREAD` a pu is ≈ 1 px on screen at 1080p (≈ 0.9 at the cover's home framing), which is what type sizes are chosen against (TREATMENT §2).
- **World units** (spread space): a page is 0.77 wide and 1 tall; the spine is at x = 0, the right page at x ∈ [0, 0.77], the left at x ∈ [−0.77, 0], the page bottom at y = 0 and its top at y = 1; the sheets lie at z ≈ 0 and the camera is above (+z).
- `pageToWorld(side, u, v)` maps pu to spread space — x = (u − 770 on the left page, u on the right) / 1000, y = 1 − v / 1000 — e.g. to aim `camera()` at something printed (the cover's push-in aims at its kiss this way).
- Up the page is always world +y: the book is only ever translated in z (the cover's drop), never moved sideways or rotated — the paper shader's wax relief and the turn shadow (computed in book x against world x) rely on it. Turn the image with the camera's `roll`.

### Faces and keyed redraw (`src/scenes/magazine/faces.ts`)

- A **face** is one side of one spread: a print layer and a marks layer, each a canvas and its texture. At most four faces are visible at once from the pages and a turn (the current left page, the turning leaf's front and back, the next right page), six with a gatefold's panels open (`MAX_FACES`, `schedule.ts`: "The fold-out" below), so `FaceCache` keeps a pool of six slots (a print and a marks canvas each) and binds them to the visible faces; a face that comes into view takes a free slot and is drawn fresh.
- Every frame the scene asks for each visible layer's `key(side, layer, t)` and redraws and re-uploads the layer only when the key differs from the one it was last drawn with (`faces.redraws` counts the redraws). A static page costs nothing per frame; a key that changes every frame costs a redraw and an upload every frame.
- **Keys are load-bearing:**
  - A key must be a pure function of `t`, and must change whenever its layer would draw differently.
  - Draw exactly the quantised state the key encodes, never the raw `t`. `layout.ts`'s `inkAt` (lyric ink in `INK_STEPS` levels) with `karaokeKey` is the reference; the cover's `state(t)` and `kissAt(t)` quantise every animation once and use the result in both. A layer drawn from the exact `t` under a quantised key shows whatever frame last redrew it, so a frame depends on the render history — preview scrubbing, what a `stills` run rendered before, the order of motion-blur sub-frames.
  - No `Math.random`, `Date.now` or `performance.now`: seed randomness with `hash`, `mulberry32` or `noise1/2/3` (`util.ts`).
- **Determinism tolerance**: face canvases are rastered by Chrome's GPU canvas, which varies by 1–2 levels at large display-glyph edges, even between two runs of the same command; byte-exact frames would need CPU-rastered faces (18–27 ms per upload). The same frame rendered twice matches with every pixel within 2 levels; a pixel more than 2 levels off is a keyed-state bug. There's no pixel count: the glyph-edge noise alone reaches 21–28 px at 1 level on hairline-stroked titles, while a stale ink key shifts whole glyphs by an `INK_STEPS` step (~12 levels), so the level bound catches it. Check: render `stills --t <t−δ>,<t>` in one run (δ a frame or two, so some keys still match) and `stills --t <t>` in another, then compare the two `t` frames.
- **Face textures**: `PX_PER_PU` sets their resolution — 2.2 px per pu at 1080p (1694 × 2200 canvases, 2.2× the open-spread framing so push-ins stay sharp), 2.2 × `SCALE` capped at 4096 px tall (4.096 px/pu at `--scale 2`, where deep push-ins soften slightly: accepted). A canvas is ~15 MB at 1080p, ~52 MB at `--scale 2`; there are twelve, plus two lipstick scratch canvases of the same size for kisses (`lipstick.ts`; every smaller canvas a spread holds marks on uses them too) and the lipstick brush's WebGL canvas, which grows to the largest stroke's box, at most a face (`waxgl.ts`).
- A canvas's premultiplied sRGB values upload as plain RGBA8 (`NoColorSpace`, `premultiplyAlpha`) and are decoded in the paper shader by `faceTex` (`src/engine/paper.ts`), which also keeps the soft edges of bright marks right. Why: an sRGB texture format sent every upload through the CPU in Chrome/ANGLE (~38 ms a face layer, against ~1 ms). Sample face textures only through `faceTex` (`faceAlphaLod` for coverage alone).
- Mipmaps are generated and sampled trilinear, and not only for minified pages: the lipstick's wax relief reads the marks layer's coverage at a fixed page-space footprint through them (`textureLod`).
- The paper shader composites the faces over the paper, so paper-coloured detail on ink is cut out of the ink (`destination-out`), not painted (TREATMENT §6).

### Page turns and the camera (`src/scenes/magazine/schedule.ts`, `src/engine/page.ts`, `src/engine/curl.ts`)

- **When**: each spread comes up at its flatplan start (`resolveFlatplan`, "Magazine" above), the cover at 0. Spread *k* comes up as spread *k*−1's right page turns, from its start, over `TURN_S` (0.55 s) on `ease.outQuart` (`magState(plan, t)`: the spread open, the turn's eased progress, and `how` it brings the next up). A rip lasts `RIP_S` (0.6 s), its progress r linear in time (`magState`'s `turnP` in a rip; `BookPose.rip`), and lands no leaf (no settle). Its motion is `page.ts`'s `ripPose(r)` (`RIP`): the leaf curls as a turn does, its hinge staying on the right pile, to 0.32 of a turn by r = 0.35 (`outCubic`), as a hand grabs it; then it tears free and flies (`inCubic`) up toward the camera and off to the upper right — moved (+0.55, +0.35, +1.6) and turned 1.1 rad about y and −0.5 about z about its spine edge's midpoint, all of it by r = 0.85, out of frame — on the turning mesh's own transform (the group stays as `checkPlacement` holds it). Its back is blank paper; it is hidden from r = 1, and its turn shadow fades out as it flies (× 1 − smoothstep(0.35, 0.6, r)). The left page stays the spread turned away from's through the rip and becomes the next spread's L face as it ends, so a spread brought up by a rip should print the old left page as its own (the ransom note draws on whoworeit's). The faces in view follow the leaves (`visibleFaces(state, plan)`), and so does the book's pose (`bookLeaves`: the piles as the spread turned away from has them, the turning leaf still on the right pile as it lifts off).
- **Camera**: from the same instant, for `CAM_BLEND_S` (0.72 s, outlasting the turn), the pose is `lerpPose` from the old spread's `camera(t)` to the new one's on `ease.inOutCubic`, pulled back by up to 6 % of the distance mid-move (on the eased progress, so the pull-back eases out with the move). Otherwise it is the `camera(t)` of the spread that is up (`spreadAt`), as is.
- **The hand** (`src/scenes/magazine/handheld.ts`): either pose is then held by hand — a slow sway, a faint tremor and a hint of roll, noise of `t` (deterministic, and every motion-blur sub-frame sees it). At `FRAME_SPREAD` it moves the image ~0.5 px typically and 1.14 px at most, a little more closer in (`(ref / dist)^0.3` times as much, capped at `maxGrow`, 1.5×); `HANDHELD.amount` scales it all (0: locked off), and `tests/handheld.test.ts` holds its bounds. It moves only x, y and roll, so the focus stays on the page.
- **Shape**: a leaf is hinged at the spine and bends as a circular arc: the angle at the spine rises 0 → π over the turn while the free edge lags (`CURL.beta`) and the top corner leads the bottom (`CURL.lead`), so the page lies flat at both ends of the turn and curls in between.
  - **The rest bow**: an open page bows up out of the gutter and lies flat beyond it (`BOW`: `h` above its hinge over `w` from the spine, `bowZ`), as much as the pile under it allows (`bowAllowed`: a page on a thin pile bows less, on none it lies flat) and only as the book opens (the cover's turn grows it, and the last turn, closing it, takes it away). The bow fades out as a leaf lifts and back in as it lands, and the stacks' tops follow it, so each page keeps lying a leaf above its stack.
  - **The settle**: a leaf that has just landed floats up a little at its free edge and settles back over 0.3 s (`SETTLE`, `settleLift`, timed from `sinceLanding` in `schedule.ts`).
  - The leaf and stack vertex shaders (`page.ts`) are generated from `curl.ts`'s constants (`BOW_GLSL` for the bow), and `curlPoint(s, u, yN, bow)` is their CPU mirror. It takes no curl of its own (nor `bowZ` a bow, nor `settleLift` a settle): the shaders are built from the frozen constants, and a variant would silently disagree with them.
- **The fold-out** (Task B3; `page.ts` `Book.panelA`/`panelB`, `schedule.ts` `foldFaces`): a gatefold spread is a `Spread<FaceSide>` and defines `panels(t): { a, b }`, each 0 (folded) to 1 (open), eased by the spread. Panel A is a leaf mirrored about the right page's outer edge (`scale.x` −1, so it turns outward), B one mirrored about A's free edge; their geometry's u is flipped back (`panelGeometry`), so every face prints upright. The spread draws one face per printed surface — `'AO'`/`'AI'` panel A's outside/inside, `'BO'`/`'BI'` B's — through `drawPrint`, `drawMarks` and `key`, and never asks which is where: `foldFaces` maps them. Folded (a = 0) no panel is posed and the right page shows `'AO'` (so does a turning leaf: a turn carries the panels folded); A lifting, the right page is `'R'`, A's front `'AO'` and its back `'BO'` (B lies folded on it, unposed); B lifting (only with a = 1), A's back is `'AI'` and B shows `'BO'`/`'BI'`. Rules, thrown on: both in [0, 1], b > 0 only with a = 1, both 0 from the spread's start until its turn in lands and from its turn out on. A lies a leaf above the right page's outer edge, following the page's bow and gutter while folded (`panelZ`, LEAF_VERT's `uBowFlip`), B a leaf above A; each shadows what it lifts off (`panelShadow`: the turn shadow mirrored about its hinge); the footprint, and so the contact shadow, widens a page per panel as it lands (`panelReach`). Frame the open centrefold with the director's `DirectorOpts.dist` (e.g. `{ min: 0.9, max: 3.6 }`: four pages fit from ~3.55; nothing else clamps the distance). `spreads/foldtest.ts` (`FOLD_TEST`, off) is a temporary test-pattern gatefold for the specimen entry.
- **Stacks**: the leaves not in play lie in two piles either side of the spine, `LEAF_EPS` a leaf (`leafZ(leaves, onLeft, turning)`); the right pile shrinks and the left one grows over the song, the rip takes a leaf off the right, and closed at the back there's no right page and no right pile: the magazine lies on the left half (its footprint, and its contact shadow on the sheets, `[−PAGE_W, 0, 0, 1]`).
- **Shadow**: the turning leaf shadows the page beneath it from the lamp. Its free edge (at mid-height), projected from the lamp (`LAMP.pos`) onto the page, is the shadow's edge, and the shadow lies between that edge and the spine — on the right page until the projected edge crosses the spine, then on the left. It takes `TURN_SHADOW` × sin(π·p) (p the eased progress) of the lamp's key there and of its reflections (the sheen, the wax); the ambient, the room's light, stays and fills it cool. Its penumbra reaches `LAMP.size` / 2 × (the edge's height above the page) / (the lamp's height above the edge) either side of the edge: soft while the leaf is up, sharp as it lands. It keeps flat-page math: the bow, a percent or two of the page's height, is left out.
- **Checking turns**: `render.ts sheet --cuts` frames every page turn (the flatplan's, from the app: `__lv.turns()`, and any timeline boundary): just before, then 1/60, 0.1 and 0.3 s after. For the landing and the camera settling as well, give it denser offsets from each turn:
  ```bash
  bun scripts/render.ts sheet --cuts --offsets 0,0.08,0.18,0.3,0.45,0.7 --cols 6 --out ../out/sheets/turns.png
  ```

### The world (`src/engine/lamp.ts`, `src/engine/paper.ts`, `src/scenes/magazine/focus.ts`)

The look is a real magazine photographed at night under a bedside lamp.

- **Render**: the scene renders the sheets and the book with a perspective camera (`LENS`: a 30° vertical field of view) into a 4× multisampled target with a depth texture, then focuses it into its output (the depth of field below). Without MSAA the page edges stair-step, and motion blur can't smooth them. The groove (`magazine/groove.ts`) covers most of its own motion with motion blur, but not the back half of every beat — once the punch has decayed, a page edge moves under a pixel per shutter for ~53% of the time while the groove runs — nor the moments a pose holds fully still: the cover (the groove is off through it), a drum stop, and the preview's single sample. MSAA keeps the edges clean wherever they move under a pixel per shutter, too little for motion blur: there, and while a pose holds fully still the camera's drift and the hand alone move an edge < 0.15 px a frame. The target costs ~120 MB of GPU memory at 1080p, ~500 MB at `--scale 2`.
- **The lamp** (`lamp.ts`): one light for every surface — the pages (`paper.ts`), their stacks (`page.ts`) and the sheets. A warm key at `LAMP.pos`, upper left above the magazine, falling off as 1 / (1 + `fall` d²), and a dim cool ambient (`amb`, `ambColor`). One exposure, computed from the lamp (`lampExposure`), lights the brightest point of a flat open spread at `LAMP.peak` on red: lit paper peaks near 0.86 linear on red, just under the tone shoulder (0.92), and falls to ~0.40 at the far corner (the right page's lower right), about half — lit paper, never paper white. Every lit surface's shader includes `LAMP_GLSL` (the constants, `lampKey`, `lampLight`), and every reflection of the lamp (the stocks' sheen, the wax, the satin) is weighted in units of the exposed key, `LAMP_KEY`, so `peak` rescales them with the diffuse light; `tests/lamp.test.ts` checks that no surface keeps a lamp of its own. The reflections follow the camera through three's own `cameraPosition` uniform, which three uploads with the view and projection matrices to every program that declares it, RawShaderMaterials included: declare it, and there's nothing to pass in.
- **Paper** (`paper.ts`; the stocks in `page.ts`): each face has a stock, `Stock` = [rough, spec, tooth]. Its sheen, the lamp's reflection in the coating, is a GGX lobe of roughness `rough` weighted by `spec`: broad and soft, it glides over the page as the camera moves, and ink takes `INK_SHEEN` (a quarter) of it, so type stays readable in it. `tooth` is how much of the paper's tooth shows (a fine static relief and mottle, ~3 pu grains). The covers' outsides are varnished (`COVER_STOCK`: a tighter, brighter lobe over a smoother surface) — the cover, leaf 0's front, and the back cover, the last leaf's back — and every other face is coated stock (`PAPER_STOCK`); `leafStock` assigns them, and a face keeps its stock through a turn (`tests/stock.test.ts`). Under any stock, the cockle, a low waviness a few cm across, breaks up the sheen. Where the sheen falls and what it costs type: TREATMENT §6.
- **The gutter** (`paper.ts` `GUTTER`): the valley between the pages hides the paper near the spine from the lamp and the room alike, so the paper darkens on both sides of the spine, whichever way the lamp falls — a deep narrow crease and a shallow broad valley, scaled by the book's opening (none while the magazine is closed) and fading out on the turning leaf as it lifts. It costs type near the spine a little light: ~8 % at 60 pu from it, ~4 % at 120 pu.
- **Focus** (`focus.ts`): a thin-lens circle of confusion from the depth, focused on the page at the camera's target (`focusDistance`: `FOCUS.pageZ` above the bed). A pixel whose circle is under `SHARP` (0.35 logical px) passes through untouched — the page, at every standard framing (`tests/focus.test.ts`), so type stays exactly as printed — and the blur fades in up to `FADE` (0.7 px), capped at `FOCUS.maxCoc`. What softens is the bed, the far edge in close push-ins, a page swinging toward the lens and the magazine in the drop (a close, tilted hold softens type away from its target: TREATMENT §6). The pass bakes in the lens's planes (`LENS`), the magazine camera's. The sheets write alpha 0, the backdrop, and get `FOCUS.backdrop` px more (depth alone can't tell them from the page lying on them), so anything else in the world, a prop added to the bed included, must write alpha 1.
- **Post**: the scene returns its post overrides, `MAGAZINE_POST` (`magazine.ts`): a lens vignette (0.35), sensor-like grain (0.035, weighted to the shadows: `grainShadow` 1) and a touch of contrast (0.12), pivoted at the lamp's brightest paper (`contrastPivot`: `LAMP.peak` × the paper's red), so lit paper stays put while the far side and the ink deepen. The diagnostic cards keep `DEFAULT_POST` ("Post" below).

### Diagnostic scenes

`?card=<name>` plays `src/scenes/<name>.ts` alone, over the whole song, instead of the magazine: `?card=testcard` (or `?card=1`) is the karaoke test card, which checks `data/lyrics.json` and `data/audio.json` against the song (the current line word by word, low-confidence words dotted, beat cells, the section strip); `?card=lipsticktest` is the lipstick — strokes, handwriting and kisses on flat paper, looping every 4 s. `render.ts --card NAME` does the same in every mode, e.g. `bun scripts/render.ts stills --card testcard --t 36`.

### Toolkit (in page units; each module's header has the details)

- `src/engine/layout.ts`: the grid — `PAGE`, `MARGIN`, `columns(side, col, span)` (12 columns with `GUTTER`), `baseline(n)` (a 12 pu grid from the top margin), `textLeft`/`textWidth`, `drawFolio`. Karaoke: `setLine(c, line, t, x, y, { family, size, align, maxWidth })` prints a lyric line at its kerned positions, unsung words as a faint ink ghost (`GHOST`), each word inking to full over its first 35 % (`inkOf`) in `INK_STEPS` levels (`inkAt`); `karaokeKey(lines, t)` is the matching key.
- `src/engine/drawing.ts`: ink illustrations that draw themselves. `makeDrawing(items, { wobble, seed })` flattens SVG path data (`M L H V C Q Z`) and polylines into strokes with cumulative lengths; `drawProgress(c, d, len)` strokes the first `len` pu in the context's current style; `hatchLines(poly, angle, spacing)` makes hatch fills; `circle`, `partial`, `subdivide`, `parsePath`.
- `src/engine/lipstick.ts` (the kiss in `kiss.ts`, re-exported): the narrator's wax — `lipstickStroke(c, pts, len, { width, seed, pressure })`, `lipstickWrite(c, text, len, opts)` (a `strokeText` or a `Drawing`; strokes that continue one another join into one pen-down run), `kiss(c, x, y, size, rot, press, lift, seed)`. Each call is one mark, inked on a canvas of its own and laid over the target source-over (the target's alpha and clip apply, its composite mode doesn't); not re-entrant. Draw into the marks layer. Strokes and writing are rasterised by a small WebGL2 brush (`waxgl.ts`) and redrawn from nothing every call: ~1 µs per pu of stroke, so a growing 2000 pu loop at width 6, or a script word, redraws in ~2–2.5 ms at either scale, ~3–4 ms with the face's clear and upload (shape by shape in Canvas2D they were ~40/70 ms and ~18/22 ms at 1080p/`--scale 2`). A kiss is still Canvas2D, ~5–7 ms a redraw at the cover's size.
- `src/engine/paper.ts`: the page-face shader (`PAPER_FRAG`, with `FACE_TEX_GLSL`): paper fibres and grain, the tooth and the cockle, ink soaking in unevenly, the lamp (`lamp.ts`), the coating's sheen per stock, the gutter's occlusion (`GUTTER`), the turn shadow, and the lipstick over the print as wax (relief, satin, glint).
- `src/engine/page.ts`: the physical magazine — `Book` (the left, turning and right leaves and the two page stacks), `Leaf`, each face's stock (`leafStock`: `COVER_STOCK` on the covers' outsides, front and back, `PAPER_STOCK` on every other face), how much of the bow each pile allows (`bowAllowed`, `leafBow`) and the turn shadow.
- `src/engine/curl.ts`: `PAGE_W`, `CURL`, `curlPoint`, the rest bow (`BOW`, `bowZ`, `BOW_GLSL`) and the settle (`SETTLE`, `settleLift`) — a leaf's shape, shared by the shaders and the CPU.
- `src/engine/lamp.ts`: the lamp (`LAMP`), its exposure and `LAMP_GLSL`, with CPU mirrors (`lampKey`, `lampLight`).

### Knobs

Safe to tune, each with what it is coupled to:

- `INK_STEPS` (`layout.ts`, 16): the levels a lyric word inks through — each level is a redraw and upload of its face, so fewer is cheaper and steppier. Keep it ≤ 35 (`karaokeKey` writes each word's level as one base-36 digit) and even (the layout tests expect exactly half ink halfway through the ink-in). The cover's own step counts (the `q(…, n)` in its `state`/`kissAt`: masthead 48, jacket and her 96, kiss 32) are the same trade.
- `GHOST` (`layout.ts`, 0.16): the opacity of unsung words. Drawing only, in no key.
- `TURN_S` (`schedule.ts`, 0.55 s): the turn's length; the camera's blend is meant to outlast it.
- `CAM_BLEND_S` (`schedule.ts`, 0.72 s) and the 6 % pull-back (`blendPose`, `magazine/view.ts`): the move between spreads' poses. `tests/schedule.test.ts` asserts that it outlasts the turn and the rip (`CAM_BLEND_S > TURN_S`, `RIP_S`) and that `camBlend` is null once it has run, and `resolveFlatplan` refuses page turns closer together than it.
- `PULL_BACK_S` (`cover.ts`, 0.3 s): the cover's camera eases from the kiss's close-up back to its home pose over this long, arriving on the flip, so the scene's blend starts from rest. `cover()` throws unless the whole kiss (press and lift) is done before it starts: `inked + KISS_PRESS_S + KISS_LIFT_S <= flipAt - PULL_BACK_S` (today's data leaves ~0.07 s).
- `CURL` (`curl.ts`, `beta` 0.6, `lead` 0.35): the bend. The shader is generated from it, so the page and its shadow stay in step. `beta` < 1 keeps every angle within 0..π; `lead` < 2 keeps the spine angle monotonic (from 2 its clamp engages: a flattened corner). The curl tests check that the page keeps its length and never dips below the table.
- `BOW` (`curl.ts`, `h` 0.012, `w` 0.11): the rest bow. The stacks follow it and the focus budget includes it (`FOCUS.pageZ`); the curl and page tests check that a bowed page never dips below the table, keeps its length, lies a leaf above its stack and never pops as a turn starts or lands.
- `SETTLE` (`curl.ts`, `a` 0.01, `hz` 2.5, `tau` 0.1, `dur` 0.3): the landing's float and settle. Keep `dur` ≤ 0.3 s, and the undershoot above the stack the page lies on (`tests/curl.test.ts`).
- `TURN_SHADOW` (`page.ts`, 0.515): how much of the lamp's key and reflections the turning leaf takes from the page beneath at mid-turn (the ambient stays). `LAMP.size` (0.3): the shadow's penumbra (never sharper than `SHADOW_SOFT_MIN`).
- `LAMP` (`lamp.ts`: `pos` (−0.6, 1.4, 1.8), `key` (1, 0.945, 0.875), `fall` 0.35, `amb` 0.08, `ambColor`, `peak` 0.97): the exposure follows it, so the brightest paper stays at `peak` wherever the lamp goes. But `pos` moves the sheen (re-derive TREATMENT §6's position), the turn shadow and the sheets' light and satin; `fall` and `amb` set how dim the far corner gets (re-run the legibility check); and a warmer `key` (less blue) turns the kiss coral — its hue must stay within 8° of #FF2E88's.
- `PAPER_STOCK` / `COVER_STOCK` (`page.ts`, [0.42, 0.68, 1] / [0.22, 0.22, 0.35]): each face's [roughness, weight, tooth]; in `paper.ts`, `INK_SHEEN` (0.25: solid black under the pages' brightest sheen stays ≤ 45/255, where 0.5 lifted it to ~55), `SHEEN_F0`, the tooth (`TOOTH_F`, `TOOTH_A`, `TOOTH_N`) and the cockle (`COCKLE_F`, `COCKLE_N`). The varnish's lobe is narrow (~0.03 rad): a tooth tilt as large (`TOOTH_N` × the cover's tooth) turns its sheen to glitter.
- `GUTTER` (`paper.ts`, `g1` 0.25 over `w1` 0.024, `g2` 0.1 over `w2` 0.12): the crease's and the valley's depth and width, at mock A's depth; deeper costs type near the spine more light.
- `FOCUS` (`focus.ts`: `aperture` 8, `maxCoc` 7, `backdrop` 2.2 px at 1080p; `pageZ` 0.02) and `SHARP` / `FADE` / `SLACK`: keep every standard framing's page under `SHARP` (`tests/focus.test.ts`, the bow included).
- `MAGAZINE_POST` (`magazine.ts`): the vignette and the contrast both cost legibility at the far corner, near a frame corner at `FRAME_SPREAD` — re-run the legibility check when tuning them. `contrastPivot` follows the lamp.
- `HANDHELD` (`handheld.ts`, `amount` 1): its tests' bounds are the spec (a pixel or two at `FRAME_SPREAD`, no jumps between frames, at most 1.6× that closer in). `MSAA_SAMPLES` keeps the edges clean wherever they move under a pixel per shutter, too little for motion blur: the cover, a drum stop and the preview's single sample, where the drift and the hand alone move an edge < 0.15 px a frame (re-measure if `HANDHELD.amount` changes); and the back half of every beat once the punch has decayed (~53% of the time while the groove runs). Elsewhere the groove's own motion is enough for motion blur to smooth.
- `SHEETS_ALBEDO` (0.6) and `SHEETS_SHEEN` (`sheets.ts`): the satin's reflectance and its sheen under the lamp.
- The lipstick's gloss (the `WAX_*` constants in `paper.ts`): the glint (`WAX_GLOSS`, `WAX_SHARP`) and the satin (`WAX_SATIN`, `WAX_SATIN_E`) are free; `WAX_BLUR` and `waxSlope`'s tap spacing go together, and the relief height `WAX_H` is tuned against both.
- Post (`DEFAULT_POST`, the engine's and the diagnostic cards'): `ca: 0` (it fringed every page edge blue and cyan), `bloomThreshold`/`bloomKnee` (bloom from 1.0 on the max channel: paper at its albedo, ~0.89, stays clear, where upstream's 0.85 would bloom every page) and `vignette: 0.08` — see "Post".

Not knobs: `FRAME_SPREAD` (type sizes, `PX_PER_PU`, the placeholders' camera drift, the focus budget, the hand's `ref` and TREATMENT §6's sheen position are all set against it); `PAGE` (`pagesize.ts`, re-exported by `layout.ts`), from which `PAGE_W` (`curl.ts`) is derived (`PAGE.w / PAGE.h`); `MSAA_SAMPLES` (`magazine.ts`; without it page edges stair-step).

## Writing a scene

The video itself is one scene (see "Magazine"): new content for it is a spread, not a scene. Scenes are for diagnostic cards (`?card=`) and for the magazine itself.

One file `app/src/scenes/<name>.ts`, default-exporting a class extending `Scene` (`src/engine/scene.ts`):

```ts
import * as THREE from 'three';
import { Scene, type Frame } from '../engine/scene';
import { FSPass, Layer2D, W, H, clearRT } from '../engine/gl';

export default class MyScene extends Scene {
  bg = new FSPass(`uniform float t; void main(){ fragColor = vec4(C_INK, 1.0); }`, { t: { value: 0 } });
  text = new Layer2D();
  async init() { /* build geometry, precompute text outlines, etc. */ }
  render(f: Frame, out: THREE.WebGLRenderTarget) {
    const { renderer, comp, lyrics } = this.ctx;
    this.bg.u.t!.value = f.t;
    this.bg.render(renderer, out);            // fullscreen shader → out (overwrites)
    const c = this.text.ctx; this.text.clear(); /* draw with Canvas2D */
    comp.draw(renderer, this.text.upload(), out); // alpha-over onto out
    return { bloom: 0.7 };                   // post overrides (optional)
  }
}
```

Rules:

- **Deterministic**: output must be a pure function of `f.t` (and seeded randomness: `mulberry32(seed)`, `hash(...)`). Never use `Math.random()`, `Date.now()` or `performance.now()` for visuals. The export averages many sub-frames per frame, in any order (see "Motion blur and sampling"). If you need simulation state (particles, feedback buffers), set `stateful = true`, reset in `reset()`, integrate with `f.dt`, and the engine will fast-forward after seeks; such a scene can only be exported with a fixed `--samples`. Renders still differ by Chrome's GPU canvas raster noise, within the tolerance given under "Magazine".
- `render()` must fully overwrite `out` (a HalfFloat linear-HDR target). Colours are **linear**; values above the tone shoulder's `k` (0.92, just above paper's ~0.89) are compressed, and only true HDR highlights should bloom (see Post below). Use palette constants (`C_INK`, `C_PAPER`, `C_LIPSTICK`… in GLSL; `LIN.ink` in TS for GL; `rgba('ink', a)` for Canvas2D).
- `ctx.params` holds the timeline entry's params (one module can serve several entries); `ctx.start/ctx.end` its window; `f.lt`/`f.p` local time/progress.
- Transitions: the video has none — its timeline is one entry, the magazine (or a `?card=` diagnostic scene in its place). The engine's transition support stays as generic code: it crossfades overlapping entries by default, and a scene that sets `handlesTransition = true` composites `f.under` (the previous scene's frame) itself using `f.tin` (0→1 over the overlap); entries whose windows touch cut hard.
- Post overrides you can return: `exposure, bloom, bloomThreshold, bloomKnee, bloomRadius, halation, ca, grain, grainShadow, contrast, contrastPivot, vignette, fade, flash, shake:[x,y], zoom, invert`. Defaults in `src/engine/post.ts`; the magazine's are `MAGAZINE_POST`.
- Performance: aim for < 25 ms/frame (measure with a quiet GPU — `render.ts perf`). Canvas2D layers are expensive to upload (upstream measured ~2–4 ms each, not re-measured here — but `Layer2D` uploads in an sRGB texture format, and in the magazine that format measured ~38 ms for a 1694 × 2200 layer against ~1 ms as plain RGBA8, see "Faces and keyed redraw"); don't use more than 2–3 per scene. Precompute in `init()`.
- Don't edit files outside your scene files (and your own helper files: `scenes/<name>-*.ts`, or a `scenes/<name>/` folder as the magazine has). Engine changes: ask the lead (report in your final message what you'd need). Do not edit `src/timeline.ts`.

## Typography

- Proportional text gets the font's kerning: whole strings through Canvas2D get it for free; glyph-by-glyph drawing must use `layout()` / `glyphX()`. Adjacent runs in different fonts or sizes have no kerning between them: set that gap by eye.
- Lyrics come with typographic punctuation (`can’t`, `’cause`): `Word.w` and `Line.text` go through `smart()`; `lyrics.get()` matches straight or curly quotes. Hardcoded display strings use ’ “ ” … – — × − too. Mono text (IBM Plex Mono) is the UI/terminal voice and keeps typewriter quotes (`plain()` for a lyric shown as typed input).
- No outlined or haloed type — with one exception: display type whose hairlines would be sub-pixel at its framing takes an opaque 0.5 pu ink stroke of itself, in its own ink (`HAIRLINE_PU`, `setLine`'s `hairline` option), which keeps the hairlines without reading as an outline.

## Palette

Print palette, one accent (`src/engine/palette.ts`, spec §3): **paper** (`#F2EDE4`, page stock), **paper2** (`#E6DFD3`, shadowed paper — gutters, undersides of folds), **ink** (`#141414`, print), **graphite** (`#8A847A`, secondary print; the test card's unsung words — the magazine's karaoke ghosts unsung words in ink at `GHOST` opacity instead), **lipstick** (`#FF2E88`) and **lipstickDeep** (`#C8155F`, its wax edge/shadow). `HEX` gives the CSS hex, `LIN` the linear-RGB triplets for GL uniforms, `rgba(key, a)` a CSS `rgba()` string. **Pink only ever means her** — the narrator, and nothing else. The magazine itself (headings, rules, the section strip, unsung lyric text) never prints in lipstick; if lipstick shows up on something that isn't the narrator, that's a bug. Diagnostic scenes (`testcard`) are exempt: their lipstick is a measurement marker (sung progress), not the narrator.

## Post (`src/engine/post.ts`)

Global post-processing runs once per frame, after all active scenes are composited: bloom, chromatic aberration, a contrast curve, a tone shoulder above paper white, grain, vignette, fades/flash, invert. Defaults (`DEFAULT_POST`, the diagnostic cards' look; the magazine returns its own, `MAGAZINE_POST`: see "The world"):

- **Bloom**: `bloomThreshold: 1.5`, `bloomKnee: 0.5` — the soft knee starts at `threshold - knee = 1.0` on the frame's max colour channel (not luminance). Diffuse paper sits at ~0.89 max channel (at most ~0.86 in the magazine's lamp), so at these defaults it stays well clear of bloom; only true HDR highlights (lipstick pushed brighter than its nominal colour by exposure or additive glow, spot gloss, etc.) bloom. The lamp's reflections add to it: the pages' sheen ~0.06, staying under the knee, and the cover's varnish ~0.25, which passes it for the flip's first frames, as the varnish sweeps across the cover (TREATMENT §6). `bloom: 0.08` is the strength; `bloomRadius: 0.75` the upsample spread. `halation: 0` by default — when used it's neutral-white (this palette has no orange, and pink is reserved for the narrator).
- **Tone shoulder** (`SHOULDER_GLSL`, shared with the engine's sampling-error estimate): below `k = 0.92` the curve leaves values completely unchanged — paper prints as paper, with about 4 sRGB levels of headroom before the shoulder engages. Above `k` a smooth exponential shoulder compresses highlights; very bright values (max channel above ~2) desaturate toward white.
- **Contrast** (`contrast: 0`, off; the magazine's 0.12): a power curve per channel, pivoted at `contrastPivot` (the scene's lit paper, at most the shoulder's `k`). Each channel below the pivot darkens: lit paper's red stays, its green and blue deepen slightly (~1–3 levels) and near-neutrals gain saturation (~12 % at 0.12). The shader multiplies by the pivot's inverse, taken on the CPU: a divide by the uniform came out one of two ways between browser sessions, and sometimes mid-session.
- **Vignette** (`vignette: 0.08`; the magazine's 0.35, a lens's): darkens paper toward the frame edges deliberately, like a photographed page — not a lens artifact to hide.
- **Fade** (`fade: 0`) and the frame with no active scene both resolve to paper (`C_PAPER`): `fade` mixes the final colour toward paper, and when no timeline entry covers `t` the engine clears straight to `LIN.paper` before post ever runs.
- **Invert** (`invert: 0`): `mix(col, C_PAPER + C_INK - col, invert)` — an exact linear-space swap of paper and ink (and everything between), not a colour-model inversion.
- `grain: 0.03` grain (two scales), stronger in mid-tones like a printed page's; `grainShadow` (0..1, the magazine's 1) weights it to the shadows instead, like a camera sensor's. `ca: 0`: chromatic aberration (px at the frame edge) is off by default — the palette has no colour but pink, and it fringed every page edge blue and cyan; it stays available for deliberate use.

## Rendering (`app/scripts/render.ts`)

The offline renderer drives the app in headless Microsoft Edge via `playwright-core`'s `chromium.launch({ channel: 'msedge', ... })`, with `--use-angle=d3d11` on Windows so it renders through the RTX 3060 Ti's D3D11 backend (`--use-angle=metal` on macOS). Edge is the default because it ships with Windows; set `LV_BROWSER=chrome` to use Chrome instead. Audio for the exported video is read from `audio/song.wav` (the same file the analysis timeline is built from — no offset between what plays and what was measured).

`render.ts` uses a Vite dev server only when `--url` names one, and then only if it is actually serving this app: it fetches the URL and checks the page for `<title>I Like Ur Look</title>` first, and fails otherwise (another project's server may hold the port). Without `--url` it always starts its own private server (`LV_NO_HMR=1`, a random port 5300–5799, `--strictPort`) and tears it down again when the render finishes, errors, or is interrupted (Ctrl-C included — it hooks `SIGINT`/`SIGTERM`/`SIGBREAK` so a private server is never left running), since a dev server already running may be another git worktree's copy of this app, or live-reloading.

The app exports a single global, `window.__lv`, that `render.ts` drives entirely through `page.evaluate()`: `still(t, samples, shutter)` renders one frame, `png()` returns the last frame as a base64 PNG, `stream(opts)` renders a time range and streams raw RGBA frames over a WebSocket for `render.ts` to pipe into ffmpeg, plus `ready`/`error`, `duration`, `errors`, `timeline`, `width`/`height`. `?export=1` selects this mode over the interactive preview (`render.ts` passes `--only`, `--scale` and `--card` on as `?only=`, `?scale=` and `?card=`); `render.ts` waits on `__lv.ready || __lv.error` before doing anything else.

## Motion blur and sampling

The export renders every frame as the average of many sub-frames spread over the shutter (`--shutter 0.2`: a fifth of the frame time, centred on the frame's time), before post-processing. `--samples N` takes N evenly spaced sub-frames; `--samples auto` chooses the count per frame (`Engine.render`, `AdaptiveSampling`):

- The count steps through 4, 12, 36, 108, 324. Each step adds a sub-frame either side of every existing one, so each set is evenly spread and centred on the frame's time.
- After each step the engine compares the new sub-frames' average with the old ones' (displayed values, worst 2×2-logical-px block). Stepped copies of a moving edge differ between the two sets; a converged streak or a still image does not. Stepping shrinks as 1/count, so the frame's remaining error is about half the change the last step made; it stops when that is below `--tol` (default 3 levels of 255).
- Upstream measurement (pdoom-video's scenes, not re-measured here): a still frame stopped at 12, ordinary camera motion at 36, and whips, slams and fast zooms at 108 or 324; at 1:1 in 4K, 108 couldn't be told from 324, while 36 still showed faint striations on the fastest edges. `render.ts` prints the sub-frame histogram of every video render.

What this asks of scenes:

- Sub-frames are rendered out of time order and in any number: a scene's output must depend on `f.t` only. `stateful` scenes can't be sampled adaptively (the engine refuses); nothing may count `render()` calls.
- Per-frame flicker and jitter keyed to 60 fps must use `frameIdx(t)` (`util.ts`), not `Math.floor(t * 60)`. `frameIdx` is constant over the frame's shutter; `floor` switches at the frame's own time and double-exposes two states in every frame.
- Noise that changes with continuous `t` (a hash seeded by time) is resampled in every sub-frame: it averages out, but slowly, and makes the adaptive sampler work harder. Seed it with `frameIdx(t)` unless it is meant to smooth out.
- A particle emitter whose rate varies over time must take the rate as a function of the birth time (with its maximum, to bound the spawn loop). A rate read at the current `t` re-times every particle from one sub-frame to the next.
- Shaders that supersample internally (4 rotated-grid taps) take `ssTap: SS_TAP` and `${SS_TAP_GLSL}` and loop `for (int k = ssK0(); k < ssK1(); k++) ... rgss(k)`, weighting by `ssWeight()`. The engine then hands each sub-frame one tap, cycling them (every set is a multiple of 4), which averages to the same image for a quarter of the cost. In the preview and single-sample stills they take all four.
- Post parameters (shake, flash, zoom, fades) are read at one point of the shutter, 1/8 of it after the frame's time (where the video was tuned, and a point every sample set includes); grain and dither are drawn once per frame.

## Output scale (4K)

`?scale=2` (render.ts `--scale 2`) renders a true 3840×2160 frame. Scenes keep laying out in logical 1920×1080 px (`W`, `H`, `ctx.W`, `ctx.H` never change), spreads in page units; the engine handles the rest:

- Render targets: `out`, the engine's targets and `makeRT()` are physical (`PW`×`PH`). `makeRT(w, h)` takes logical px and allocates `w*SCALE`×`h*SCALE`; pass `{ pxScale: 1 }` for a data-sized target whose resolution must not follow the output.
- `Layer2D`: the backing canvas is `SCALE`× larger and its context is pre-scaled, so drawing code works in logical px. `setTransform`/`resetTransform`/`getTransform`, `shadowBlur`, `shadowOffsetX/Y` and `filter` px lengths are patched to stay logical. Not patched: `canvas.width/height` and `getImageData`/`putImageData` are physical px, and `drawImage(layer.canvas, x, y)` needs an explicit size. `new Layer2D(w, h, 1)` makes a deliberately low-res layer (e.g. a soft glow). `scaleContext2D(ctx, SCALE)` applies the same patch to your own canvas.
- `LineBatch`: coordinates and widths stay logical; the AA feather and the hairline floor work in physical px, so hairlines stay crisp.
- GLSL (`GLSL_COMMON`): `gl_FragCoord`, `fwidth` and `dFdx` are physical. Use `FRAG_PX` (the fragment position in logical px) instead of `gl_FragCoord.xy` whenever it is combined with logical sizes, and `PX_SCALE` to convert. A line whose width comes from `fwidth` ("a 1.2 px hairline": `1.0 - smoothstep(a, b, d / fwidth(u))`) gets thinner and fainter at 4K: write it as `pxLine(d, a, b)`, which is identical at 1× and keeps the 1× ink with sharper edges at 4K (`rampLine` does the same for the linear-ramp idiom). `hatch`, `engrave` and `aaStroke` already do this. LOD thresholds and supersampling offsets expressed in pixels should be logical (`fwidth(u) * PX_SCALE`, offsets `/ PX_SCALE`).
- Offscreen canvases used as textures (atlases, text planes) keep their own size: make them `SCALE`× larger (with `ctx.scale(SCALE, SCALE)`) if they are shown large, or they look soft at 4K. The magazine's face canvases do, through `PX_PER_PU` (capped at 4096 px).
- Post (bloom, halation, CA, grain, vignette) scales automatically; the bloom pyramid stays at the logical resolution.
